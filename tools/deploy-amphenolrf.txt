DEPLOY AMPHENOL RF A PRODUCCIÓN
==============================

PREREQUISITO (lo hace el usuario por Avada, NO es parte de estos pasos)
   - Fabricante "Amphenol RF" (slug: "amphenol-rf") ya creado en el admin
     con su plantilla (post con [catalogo]) asociada.
   - tree_layout recomendado: "table_desc".

1) SUBIR ARCHIVOS A tools/ EN PRODUCCIÓN
   - amphenol-rf-categorias.csv (NUEVO: reemplaza categoriasamphenolrf.csv)
   - amphenol-rf-productos.csv (NUEVO: reemplaza productosamphenolrf.csv)
   (los tools .php del plugin ya deben estar desplegados:
    full-import.php, import-rf-structure.php, pack-catalog.php, etc.)
   - Código fuente del plugin ya desplegado con estos cambios:
        * src/Import/Processors/AmphenolRfProcessor.php (ACTUALIZADO: ahora
          parsea pdf_url y cad_url del CSV en $data['pdf'] — antes los saltaba
          intencionalmente porque el CSV viejo no tenía URLs válidas)
        * src/Import/ProcessorManager.php (registro del procesador amphenol-rf)
        * src/PublicFacing/Views/catalog-render-html.php (amphenol-rf en show_features_col)
        * src/Import/BatchProcessor.php (fix: saltar categorías con products_count=0
          en el agrupado, evita páginas grouped vacías)

2) IMPORTAR PRODUCTOS (REMPLAZA todo RF: borra categorías y reimporta productos)
   cd /home2/hosting158857eu/public_html/tc-componentes.es/wp-content/plugins/aoe-catalog-engine
   nohup php -d register_argc_argv=1 tools/full-import.php --manufacturer=amphenol-rf --csv=/home2/hosting158857eu/public_html/tc-componentes.es/wp-content/plugins/aoe-catalog-engine/tools/amphenol-rf-productos.csv --mode=replace > import-rf.log 2>&1 &

   Monitorear: tail -f import-rf.log
   Debe terminar con "Importación finalizada" y "pack_catalog completado".
   (En este punto todos los productos quedan en Uncategorized porque las
    categorías no existen todavía; se arregla en el paso 3.)
   En local tardó ~125s por 11.616 filas; en prod puede ser similar.

3) RECONSTRUIR CATEGORÍAS + RE-ADJUNTAR PRODUCTOS + PODAR VACÍAS
   php /home2/hosting158857eu/public_html/tc-componentes.es/wp-content/plugins/aoe-catalog-engine/tools/import-rf-structure.php

   Esto hace:
     - L1 familias + L2 subcategorías con metadata rf_id + url, descripción
     - Uncategorized fallback
     - Re-adjunta los productos por SKU -> category_l2
     - Poda las categorías sin productos ni hijas con data (bottom-up, preserva Uncategorized)
     - Actualiza products_count
     - Regenera las páginas (pack_catalog)

   Salida esperada:
     Categorias CSV: 174
     SKUs en CSV de productos: 11616
     Productos en DB: 11616
     Insertadas: L1=7 L2=167 | fallback: uncategorized
     Products re-attribute: 11616 | to uncategorized: 0
     Pruned empty categories: 7
     === Resumen ===
     Insertadas L1=7 L2=167 | fallback: uncategorized | despues prune: 168
     Regenerando paginas...
     Paginas regeneradas.

4) VERIFICAR
   a) Árbol /catalogo/amphenol-rf/
      - Cada L1 como heading con sus L2 debajo como TABLA con link.
      - Los conteos (n) en las L2 y links a cada página de categoría.

   b) Páginas de categoría: toda L2 con productos tiene URL propia y paginación.

   c) Página de producto (clic en una fila)
      - Fila-producto con imagen
      - Columna de especificaciones técnicas (specs) con badge "Características"
      - ICONOS DE DOCUMENTOS: ahora sí aparecen PDF (datasheet) y 3D CAD en la
        columna de acciones. ~11.141 de 11.616 productos tienen docs.
        Los que no tienen simplemente no muestran icono.

   d) Imágenes: se sirven desde la URL remota (S3) del fabricante.
      - 1.745 productos usan el placeholder search-parts.svg y renderizan SIN imagen.

   e) NO debe existir /catalogo/amphenol-rf/productos/ (página grouped vacía).

   f) LIMPIAR CACHÉ del catálogo en prod:
      borrar wp-content/uploads/aoe-cache-catalog/amphenol-rf/

NOTAS
   - El orden importa: full-import --mode=replace BORRA todas las categorías RF.
   - 11.616 productos; ~11.141 con docs (pdf_url/cad_url), ~9.871 con imagen.
   - 168 categorías finales: 7 L1 + 161 L2.
   - PDFs/CAD ahora funcionan: el processor guarda las URLs como JSON en url_pdf.
