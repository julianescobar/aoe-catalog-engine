DEPLOY AMPHENOL CONEC A PRODUCCIÓN
=================================

PREREQUISITO (lo hace el usuario por Avada, NO es parte de estos pasos)
   - Fabricante "Amphenol Conec" (slug: "amphenolconec") ya creado en
     el admin con su plantilla (post con [catalogo]) asociada, igual que los demás.
   - tree_layout recomendado: "table_desc" (mismo criterio que Edac/Bulgin/RF/Lutze).
   - post del fabricante: wp_post_id 10492, config_json con media_source local.
     En local es el id 14 de la tabla aoe_catalog_manufacturers.

1) SUBIR ARCHIVOS A tools/ EN PRODUCCIÓN
   - conec_categorias.csv
   - conec_productos.csv
   - import-conec-structure.php
   (los tools .php ya desplegados: full-import.php, repack-catalog.php, etc.)
   - Código fuente del plugin ya desplegado con estos cambios (los .php no se
     copian en tools/):
       * src/Import/Processors/AmphenolConecProcessor.php (nuevo; threshold 1;
         categorías separadas 2 niveles; matching por conec_id = ruta compuesta
         "L1|L2" en metadata_json con fallback a L1; imágenes remotas (se filtra
         el placeholder de Magento -> filas sin imagen); docs datasheet +
         Documento N (pdf_extra) + 3D CAD (STEP zip); specs desde attrs JSON
         (labels en inglés, todos técnicos, sin filtros); descripción del
         producto: array JSON de líneas unidas con ", " para la línea de
         subtítulo de la fila)
       * src/Import/ProcessorManager.php (registro del procesador amphenolconec)
       * src/PublicFacing/Views/catalog-render-html.php (amphenolconec en
         show_features_col para la columna "Características"; descripción de la
         página de categoría con bullets como amphenolltw/amphenolindustrial)
       * src/PublicFacing/Views/single-catalog.php (conversión GENÉRICA de
         descripciones "•" a <ul><li> en el árbol de categorías; ya no está
         limitada a amphenolltw. Sin cambio de comportamiento para fabricantes
         con texto plano)

2) IMPORTAR PRODUCTOS (REMPLAZA todo Conec: borra categorías y reimporta productos)
   cd /RUTA_DEL_SITIO/wp-content/plugins/aoe-catalog-engine
   nohup php tools/full-import.php --manufacturer=amphenolconec --csv=tools/conec_productos.csv --mode=replace > import-conec.log 2>&1 &

   Monitorear: tail -f import-conec.log
   Debe terminar con "Importación finalizada" y "pack_catalog completado".
   (En este punto todos los productos quedan en Uncategorized porque las
    categorías no existen todavía; se arregla en el paso 3.)
   Ojo: en local tardó ~101s por 10.085 filas; en prod puede ser similar.

3) RECONSTRUIR CATEGORÍAS + RE-ADJUNTAR PRODUCTOS + PODAR VACÍAS
   php tools/import-conec-structure.php

   Esto hace:
     - L1/L2 con slugs jerárquicos (padre+propio, evita colisiones de nombres
       repetidos como "Enclosure technology" bajo distintas familias) y metadata
       conec_id + url
     - Descripciones: el CSV trae arrays JSON de párrafos; se guardan como
       texto con bullets "•" para que el render las muestre como <p>+<ul><li>
     - Imágenes de categoría (URLs remotas conec.com)
     - Uncategorized fallback
     - Re-adjunta los productos por SKU -> category_l1|l2 (del CSV de productos)
       con fallback a L1 si la ruta no existe
     - Poda las categorías sin productos ni hijas con data (bottom-up, preserva Uncategorized)
     - Actualiza products_count
     - Regenera las páginas (pack_catalog)

   Salida esperada (aprox, local):
     Categorias CSV: 51
     SKUs en CSV de productos: 10085
     Productos en DB: 10085
     Insertadas: L1=8 L2=43 | fallback: uncategorized
     Products re-attribute: 10085 | to uncategorized: 0
     Pruned empty categories: 8
     === Resumen ===
     Insertadas L1=8 L2=43 | fallback: uncategorized | despues prune: 44
     Regenerando paginas...
     Paginas regeneradas.

4) VERIFICAR
   a) Árbol /catalogo/amphenolconec/
      - 8 familias L1 como headings con su descripción: párrafo intro +
        <ul class="aoe-cat-bullets"> (los "•" del CSV se convierten a ul/li).
      - L2 debajo como tabla con links y conteos.

   b) Páginas de categoría: toda L2 con productos tiene URL propia y paginación
      (las grandes paginadas de a 200, p.ej.
      /catalogo/amphenolconec/d-sub-connectors-d-sub-standard-high-density/).
      Top categorías (link_count total): ver con
      SELECT slug, link_count FROM wp_aoe_catalog_pregenerated_pages
      WHERE manufacturer_id = <id> AND type = 'category' ORDER BY link_count DESC;

   c) Página de producto (clic en una fila o iconos)
      - Fila-producto con imagen (se sirve remota desde conec.com; el render con
        media_source=local cae a la URL remota si no hay archivo local)
      - Subtítulo de la fila: descripción del producto (array JSON de líneas
        unidas con ", ", p.ej. "D-SUB contacts, Plug, Crimp, Quality class 3")
      - Columna de especificaciones técnicas (specs) con badge "Características"
        (labels en inglés tal cual del CSV attrs, sin ruido comercial)
      - Iconos de acción: imagen, documentos (PDF) y ficha técnica.
      - PDFs: botón "Datasheet" + "Documento N" (pdf_extra). Remotos.
      - 3D CAD: los productos con cad_url lo muestran en el modal bajo "3D CAD"
        (archivos .zip STEP de conec.com).

   d) NO debe existir /catalogo/amphenolconec/productos/ (página grouped vacía).
      Con threshold 1 no se generan grouped; si quedara un grouped con 0
      productos, borrarlo.

   e) LIMPIAR CACHÉ del catálogo en prod para ver el render nuevo:
      borrar wp-content/uploads/aoe-cache-catalog/amphenolconec/

   f) Si en prod solo cambia el renderizador (single-catalog.php / catalog-render-html.php)
      sin reimportar, regenerar las páginas con:
      php tools/repack-catalog.php amphenolconec

NOTAS
   - El orden importa: full-import --mode=replace BORRA todas las categorías
     Conec, por eso el paso 3 reconstruye las categorías después.
   - 10.085 productos en DB (el CSV trae 10.085 filas, sin duplicados de SKU).
   - 51 categorías en CSV: 8 L1 + 43 L2; tras prune quedan 44 (8 L1 + 35 L2 +
     1 uncategorized como L1). 0 a uncategorized. Las 8 podadas no tienen
     productos ni hijas con data (p.ej. "Gehäusetechnik").
   - Cobertura: 8.533 con imagen (el resto son productos cuyo image_url era el
     placeholder de Magento y se filtran -> sin imagen), 7.654 con pdf
     (datasheet + Documento N), 6.213 con 3D CAD, 10.076 con specs, todos con
     product_url.
   - El CSV es UTF-8 (con BOM) y los caracteres alemanes (Gehäusetechnik, °C)
     se guardan e renderizan correctamente.
   - Specs attrs: 168 labels, todos técnicos en inglés, sin ruido comercial
     (sin price/packing/order), por eso no hay lista de labels ignorados.
   - Descripción de producto: array JSON de líneas -> una sola línea unida con
     ", " (se renderiza como subtítulo bajo el nombre en la fila). Fácil de
     cambiar si el cliente lo pide.
   - Páginas generadas: 1 tree + 82 category (0 grouped, 0 slugs duplicados).
   - AOE_DB_HOST=127.0.0.1:10006 es solo para local (bypass del socket de Local).
